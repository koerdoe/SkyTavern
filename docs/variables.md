# 变量与正则

变量让卡片有“状态”：血量、金钱、地点、好感度……正则脚本负责把模型的回复变成变量操作，或者改变消息的显示效果。HTML 组件则让玩家直接在消息里点按钮改变量。

## 变量

### 变量挂在楼层上

变量不单独存储。每一层消息可以带若干**操作**，当前值是从初始值开始，沿着当前选用的候选逐层重放得到的：

```
初始         hp = 100, gold = 60
第 3 层      hp -= 15
第 6 层      gold -= 5, location = "集市"
→ 当前       hp = 85, gold = 55, location = "集市"
```

所以：

- **重新生成、切换候选、删除消息**，变量自动跟着变，不需要回滚。
- 某一层的操作改了，它之后的所有值都会重新计算。

### 值的类型

| 类型 | 写法 |
|---|---|
| 数字 | `100`、`-2.5` |
| 文字 | `"酒馆"` 或 `'酒馆'`，必须加引号 |
| 真假值 | `true`、`false` |
| 列表 | `["草药", "火绒符"]` |
| 对象 | `{ 价格: 30, 货币: "金币" }`，字段名可以不加引号 |

列表和对象可以嵌套，也可以跨多行写，允许末尾多一个逗号：

```
商品 = {
  灵泉水: { 价格: 30, 库存: 5 },
  火绒符: { 价格: 15, 库存: 8 },
}
```

### 用 . 取到里面

变量名可以用 `.` 一路取下去：对象取字段，列表按序号取第几项（从 0 开始）。

```
商品.灵泉水.库存 -= 1
背包.0 = "破损的草药"
```

给不存在的字段赋值时，路径上缺的对象会自动建好：`钱包.金币 = 100` 会得到 `钱包 = { 金币: 100 }`。

### 操作

只有三种，作用取决于变量当前的类型：

| 写法 | 数字 | 文字 | 列表 | 对象 |
|---|---|---|---|---|
| `=` | 赋值 | 赋值 | 整个替换 | 整个替换 |
| `+=` | 相加 | 接在后面 | 末尾追加一项 | 合并字段（同名的覆盖） |
| `-=` | 相减 | — | 删掉第一个相等的项 | 删掉一个字段（值写字段名） |

```
hp -= 15
背包 += "灵泉水"          // 列表追加
背包 -= "草药"            // 列表删掉一项
商品 += { 雷鸣贝: { 价格: 45, 库存: 3 } }
商品 -= "火绒符"          // 对象删掉一个字段
```

- **第一次赋值决定类型**。`hp` 一开始是数字，之后就不能赋值成文字；对象里的每个字段也一样。
- `+=`、`-=` 只能用于已经存在的变量。
- 变量不能整个删除，但可以删掉列表里的项、对象里的字段。
- 变量名以文字或 `_` 开头，可以包含数字；`.` 用来取里面的内容。
- `char`、`user` 以及以 `$` 开头的名字是系统保留的，只能读不能改。

不合规则的操作不会生效，也不会阻止生成，只在消息下面标红，见[消息下的变量](#消息下的变量)。

### 算式与分支（不推荐）

原则上支持，但**不推荐**：算式和分支很容易写出意料之外的结果，状态类玩法优先用固定的值和组件。

值不是固定的值时，按算式求值（和 [IF 条件](request-structure.md#if-条件) 同一套写法）：

```
hp -= 伤害 * 2
连击 = 连击 + 1
```

分支用 `if` / `elif` / `else` / `end`，可以嵌套：

```
if hp <= 0
  状态 = "倒下"
elif hp < 30
  状态 = "重伤"
else
  状态 = "正常"
end
```

- 算式和条件在**重放到这一层时**求值，读的是那一刻的变量。所以它们只能用在聊天里（编辑块、手动编辑、组件提交），**初始变量只能写固定的值**——那时还没有聊天记录，变量还不全。
- 每个条件只在执行到 `if` 时求值一次，选中的那一支里的操作依次执行。
- 求值失败（例如读到不存在的变量、除以 0）时，这条操作不生效，消息下面标红，不会中断生成。
- 不加引号的文字会被当成算式里的变量名：`地点 = 酒馆` 读的是变量“酒馆”。想写文字要加引号。
- 文字和数字不能直接相加：`"hp " + hp` 会出错。

### 初始变量

预设和角色卡都可以写一份初始变量（预设在左栏齿轮设置里，角色卡在右栏详情里），每行一个 `名称 = 值`：

```
hp = 100
gold = 60
location = "村口"
```

两份同时生效，同名时**角色卡的覆盖预设的**（按最外层的名字整个覆盖）。初始变量只能用 `=`，可以写列表和对象，也可以用 `.` 给字段赋值。

### 在哪里读取变量

- 词条的 **IF** 条件：`hp < 30`、`商品.灵泉水.库存 > 0`、`len(背包) > 0`，见[请求结构](request-structure.md#if-条件)。
- 词条内容里的**占位符**：`当前生命 {{hp}}`。列表和对象会展开成 JSON，例如 `{{商品}}` 得到整张货架，适合放在正文后给模型看当前数据。
- 读取的是本次请求用到的聊天记录重放后的值。

> 在正文前用 `{{hp}}` 这类会变的占位符会让缓存失效。状态类内容建议放在正文后或 D0。

## 编辑块：让模型改变量

在回复里写一个 `<var>` 编辑块，每行一个操作：

```
艾琳拔出短剑，挡下了这一击，但手臂还是被划开一道口子。

<var>
hp -= 15
location = "北门"
</var>
```

回复收下时，编辑块会被取出：里面的操作挂到这一层，编辑块本身从正文里删掉，不会显示，也不会再发给模型。

- 空行和 `//` 之后的注释会被忽略；列表和对象可以跨行。
- 一条回复可以有多个编辑块。
- 没闭合的编辑块（例如回复被截断）留在正文里，不生效。
- 用户消息里的编辑块同样有效。

要让模型写编辑块，在预设或角色卡里写一条说明格式的词条就行。如果模型更习惯别的格式（例如 `【伤害15】`），用返回时正则把它转成编辑块，见下文。

## 正则脚本

正则脚本是作者写的查找替换规则，挂在预设或角色卡上。点顶栏的**正则**可以看到当前预设和角色卡的全部正则，按执行顺序排列，并在这里新增和编辑。

### 何时执行

| 类型 | 什么时候 | 改的是什么 |
|---|---|---|
| **返回时** | 消息进入会话时执行一次 | 存下来的正文。可以产生编辑块 |
| 运行时 · 只作用于显示 | 每次显示时 | 只改界面上看到的，不改存下来的正文 |
| 运行时 · 只作用于请求 | 每次发送时 | 只改发给模型的聊天记录 |
| 运行时 · 显示和请求 | 两者都有 | 同上 |

返回时正则对以下消息执行：

- 模型的回复，包括中途停止、只收到一部分的回复。
- 你发出的消息。

手动编辑消息时不会再执行，改的就是你写的内容。需要时可以用下面的“重新执行”。

它先于编辑块提取执行，所以替换结果里可以写 `<var>`：

```
正则：     【伤害(\d+)】
替换为：   <var>hp -= $1</var>
```

运行时正则只作用于聊天记录，不作用于词条。

### 动作：替换，或者固定插入

| 动作 | 做什么 |
|---|---|
| 替换匹配到的文字 | 用正则查找，按“替换为”的模板替换 |
| 插到消息开头 | 把内容原样放在消息最前面 |
| 插到消息末尾 | 把内容原样放在消息最后面 |

插入的内容和正文之间自动隔一个空行，**原样插入**，不处理 `$1` 这类写法，所以可以直接放一整段带脚本的 HTML 组件。插入时正则可以留空（总是插入）；写了就只在消息里能匹配到时才插入。

最常见的用法是固定挂一个组件：运行时 · 只作用于显示 · 插到消息末尾 · 只作用于最新一条，内容是一段 ```` ```html ```` 代码块。见[万界商铺](#示例万界商铺)。

### 其他设置

- **作用于**：用户消息、AI 回复，可以都选。
- **只作用于最新一条**（仅运行时）：只处理所选角色里最后一条消息。例如只在最新的 AI 回复下面挂商店，旧消息保持原样。作用于请求时要注意：上一轮的“最新一条”到下一轮就不是了，那条消息的内容会变，缓存会从那里断开。
- **标志**：`g` 替换全部匹配（不加只替换第一处），`i` 忽略大小写，`m` 多行，`s` 让 `.` 匹配换行，`u` Unicode。
- **替换为**：`$1`、`$&`、`$<名字>`、`$$` 的写法和插入法模板一样，引用不存在的组不能保存。
- **优先级**：大的先执行；相同时预设的在前，再按 ID。后执行的看到的是前面替换后的文字。

### 试一试

编辑正则时，在“试一试”里粘贴一段文字，立刻看到替换结果和取出的变量操作。这只用当前这一条正则，不影响会话。

### 对已有消息重新执行

返回时正则只在消息进入会话时执行一次。改了正则之后，已有的消息不会自动变化。要补处理，点正则窗口底部的**对当前会话重新执行**：对已加载的全部楼层重新执行返回时正则，改写正文，取出的变量操作追加到对应楼层。

### 出错时

- 正则写错（例如括号不配对）不能保存。
- 服务器上执行的正则超过 5 秒没完成（通常是回溯失控，例如 `(a+)+`）会被终止：
  - 返回时正则：**回复照常保存**（保留原文），原因记在这条消息上。
  - 作用于请求的正则：这次不发送，提示是哪条正则。

## 消息下的变量

带变量操作的消息下面有一排小标签：

| 颜色 | 含义 |
|---|---|
| 绿色 | 已生效，例如 `hp −15`。悬停看来源（编辑块、组件、手动） |
| 红色 | 重放时不能执行，例如类型不对、变量还不存在。悬停看原因 |
| 黄色 | 编辑块里有写错格式的行，没有生效。悬停看是哪一行 |

消息的工具按钮里有一个**变量**按钮（悬停提示“这一层的变量操作”），可以直接改这一层的全部操作（和编辑块同样的写法）。改完之后面的值会重新计算。

## HTML 组件

回复里的 ```` ```html ```` 代码块会显示成一个可交互的组件，例如商店、状态面板、选项按钮。

````
```html
<p>商人：要买点什么？</p>
<button id="buy">药水（5 金币）</button>
<p id="info"></p>
<script>
  const info = document.getElementById('info');
  const show = async () => { info.textContent = '金币：' + (await sky.vars()).gold; };
  document.getElementById('buy').onclick = async () => {
    sky.sub('gold', 5);
    sky.add('hp', 20);
    await sky.commit();
    show();
  };
  show();
</script>
```
````

代码块可以由模型写，也可以用返回时正则或运行时显示正则生成（例如把 `【商店】` 替换成一整段组件）。组件本身会原样发给模型；不想发送的话，加一条“只作用于请求”的正则把它去掉。

### 能做什么、不能做什么

组件运行在隔离的沙箱里：

- 可以运行自己的脚本和样式，可以显示外部图片和音视频。
- 不能加载外部脚本和样式表，不能用脚本发网络请求，也不能访问 SkyTavern 页面本身。

组件的背景是透明的，字体和颜色跟随白天/夜晚模式。可以直接用这些 CSS 变量：`--text`、`--text-2`、`--accent`、`--border`、`--surface`、`--surface-2`。高度会随内容自动调整。

### window.sky

| 调用 | 作用 |
|---|---|
| `await sky.vars()` | 这一层执行完之后的全部变量（不含尚未提交的修改） |
| `await sky.chat(n)` | 到这一层为止最近 n 条消息（默认 10，最多 50），每条是 `{ role, content }` |
| `sky.set(名, 值)` | 暂存一个赋值（`=`），值可以是列表、对象 |
| `sky.add(名, 值)`、`sky.sub(名, 值)` | 暂存 `+=`、`-=` |
| `sky.note(文字)` | 暂存一条[附加消息](#附加消息)，再次调用会替换 |
| `sky.staged()` | 查看暂存的修改 |
| `sky.discard()` | 丢弃暂存的修改和附加消息 |
| `await sky.commit()` | 把暂存的修改写成**这一层**的变量操作，连同附加消息一起写入，返回写入的操作条数 |

变量名同样可以用 `.`，例如 `sky.sub('商品.灵泉水.库存', 1)`。

修改在 `commit()` 之前只存在组件里，可以让玩家先挑选、再确认。提交后的操作来源标为“组件”，和编辑块一样挂在这一层：重新生成或切换候选时，它们跟着那个候选走。

## 附加消息

组件可以在提交时附上一条**附加消息**，比如“本轮在商店买了什么、卖了什么、钱包怎么变了”。它不是正文：

- **显示**：在这条消息末尾，一张虚线框的卡片。可以点 × 删除（删除不会撤销变量）。
- **发送**：下一轮作为一条 **user 消息**，紧跟在这条消息之后、你的下一句话之前。于是模型看到的是：

```
assistant  （老板的回复）
user       【商店记录】购买：灵泉水 ×2（60 金币）……
user       （你的下一句话）
```

- 同一条消息上提交了多次，合成一条发送。
- 附加消息挂在这个候选上：重新生成或切换候选时跟着走。
- 计算 Dx 深度时不单独计数，算作它所属那条消息的一部分；正文裁剪时也跟着那条消息一起裁掉。
- 预览里标为“附加消息”。

大多数模型不要求 user 和 assistant 严格交替，连续两条 user 消息可以正常发送。

## 示例：万界商铺

新账号自带一张示例角色卡「万界商铺」（你扮演顾客，AI 扮演老板）和它的世界书「万界商铺 · 账本」，把上面这些功能串在一起：

| 部分 | 在哪 | 做什么 |
|---|---|---|
| 初始变量 | 角色卡 | `货币`（钱包）、`背包`、`商品`（货架）、`收购`（老板额外收的东西），都是对象 |
| 经营规则 | 角色卡词条（正文前） | 告诉模型怎么上架、下架、改库存、调价、收购、发钱，两种写法都教：简短指令和编辑块 |
| 指令正则 ×7 | 角色卡正则（返回时） | 把 `【上架\|雷鸣贝\|45\|金币\|3\|描述】` 这样的指令转成编辑块 |
| 货架组件 | 角色卡正则（运行时 · 显示 · 插到末尾 · 只作用于最新一条） | 在最新的 AI 回复下面挂一个可以买卖的货架 |
| 商店记录 | 组件结账时的附加消息 | 下一轮随你的话一起告诉老板刚才的交易 |
| 账本 | 世界书词条（正文后，user） | 用 `{{商品}}`、`{{货币}}` 等占位符把当前数据给模型看，不破坏前面的缓存 |

想做自己的带状态卡片时，可以从这张卡复制一份再改。

旧账号不会自动加上这张卡（只有新账号在第一次使用时写入默认资料）。
