# 导入

右栏“角色”或“世界书”列表上方的导入按钮（向下箭头）可以导入：

- 酒馆（SillyTavern）的角色卡：V1、V2、V3，JSON 文件或者把卡藏在图片里的 PNG。
- 酒馆的世界书 JSON。

可以一次选多个文件。导入完会列出每个文件的**报告**：和酒馆不一样的地方，以及被停用的词条和原因。

> 我们保证能导入，但不保证效果和在酒馆里一模一样。转换不了的东西照样导入，只是先停用，修好后再启用。

## 角色卡

| 酒馆字段 | 导入后 |
|---|---|
| name、tags | 名称、标签 |
| description + personality | “角色设定”词条（正文前，3000）；性格接在描述后面 |
| scenario | “场景”词条（正文前，2000） |
| mes_example | “对话示例”词条（正文前，500） |
| first_mes | 开场白 |
| alternate_greetings | 其他开场白：新会话第一条消息的其他候选，左右切换 |
| creator_notes | 作者备注（只给人看，不发给模型） |
| system_prompt | “卡片系统提示”词条，**停用**：提示词应该由预设管，需要时手动启用 |
| post_history_instructions | “卡片历史后指令”词条（正文后），**停用**，理由同上 |
| 角色备注（depth_prompt） | 正文 Dx 词条；原本是 system 角色的改成 user |
| 内嵌世界书（character_book） | 导入成一本独立的世界书，并关联到这张角色卡 |
| 卡片自带的正则 | 正则脚本，见下文 |
| PNG 图片 | 头像（去掉了图片里的卡片数据） |

卡片引用了外部世界书（不在卡里的）时，报告里会提示你单独导入。群聊专用开场白、脚本插件等扩展数据不导入。

## 世界书

### 位置和优先级

| 酒馆位置 | 导入后 |
|---|---|
| 角色定义前 | 正文前，优先级 5000 起 |
| 角色定义后 | 正文前，优先级 1000 起 |
| 作者注释上 / 下 | 正文 D4（我们没有作者注释，酒馆作者注释的默认深度是 4） |
| @深度 | 正文 Dx，保留角色（system 改成 user） |
| 对话示例上 / 下 | 正文前，优先级 600 / 400（对话示例是 500） |
| outlet | 不支持，停用 |

酒馆里 order **越大越靠近末尾**；我们优先级越大越靠前。所以导入时在 0–999 的范围内倒过来：`优先级 = 基础 + 999 − order`。例如角色定义前、order 100 的条目，导入后是 5899。顺序和酒馆一致，只是数值不同。

### 关键词触发

我们没有单独的触发系统，关键词直接转成 [IF 条件](request-structure.md#if-条件) 里的 `mentioned()`：

| 酒馆 | IF |
|---|---|
| 常驻（蓝灯） | 没有条件 |
| 关键词 艾琳、Eileen | `mentioned(2, "艾琳", "Eileen")` |
| 次要关键词，与任意（AND ANY） | `mentioned(2, "灯塔") && mentioned(2, "夜", "雨")` |
| 与全部（AND ALL） | `… && mentioned(2, "夜") && mentioned(2, "雨")` |
| 非任意（NOT ANY） | `… && !mentioned(2, "夜", "雨")` |
| 非全部（NOT ALL） | `… && !(mentioned(2, "夜") && mentioned(2, "雨"))` |

第一个数字是检查最近几条消息：用条目自己的扫描深度，没写的按酒馆默认 2 条。`/正则/` 写法的关键词照样支持。

这些词条若在正文前，按内容触发会让缓存失效，风险检查会提示；挪不挪由你决定。

### 向量触发

酒馆里勾了“向量化”的条目转成 [`similar()`](request-structure.md#按相似度触发-similar)：用条目自己的内容和最近几条消息比相似度。

| 酒馆 | IF |
|---|---|
| 只有向量触发 | `similar(2)` |
| 向量触发 + 关键词 | `similar(2) \|\| (mentioned(2, "铁门"))`（满足其一） |

数字同样是扫描深度。要生效，得在系统设置里打开召回并选好嵌入模型；没开时这些条目按不成立处理，预览里会提示。

### 不支持、已忽略的

报告里会汇总列出：

- 触发概率：忽略，条件满足就触发。
- 区分大小写、关闭整词匹配：我们的 `mentioned()` 不区分大小写，英文关键词总是按整词匹配。
- 黏性、冷却、延迟、包含组、递归：忽略。
- 没有关键词又不是常驻的条目：酒馆里永远不会触发，停用。

## 宏

| 酒馆 | 导入后 |
|---|---|
| `{{char}}` `{{user}}` `<BOT>` `<USER>` | `{{char}}` `{{user}}` |
| `{{time}}` `{{date}}` `{{weekday}}` `{{isotime}}` `{{isodate}}` | `{{$time}}` `{{$date}}` `{{$weekday}}` |
| `{{lastMessage}}` `{{lastUserMessage}}` `{{lastCharMessage}}` | `{{$lastMessage}}` `{{$lastUserMessage}}` `{{$lastCharMessage}}` |
| `{{newline}}` | 换行 |
| `{{// 注释}}` `{{trim}}` `{{noop}}` | 删除 |
| `{{getvar::金币}}` | `{{get("金币")}}`：变量不存在时是空文字，和酒馆一样 |
| `{{random::a::b}}` `{{random:a,b}}` | `{{random("a", "b")}}`：每次请求重新抽 |
| `{{pick::a::b}}` | `{{pick("a", "b")}}`：同一个会话里固定 |
| `{{roll:1d20}}` | `{{roll("1d20")}}` |
| `{{setvar::hp::100}}` | 编辑块 `hp = 100`（只在开场白和返回时正则里，见下文） |
| `{{addvar::背包::铜镜}}` `{{incvar::回合}}` `{{decvar::回合}}` | 编辑块：变量存在就 `+=` / `-=`，不存在就直接赋值（和酒馆一样从空值算起） |
| 全局变量版本（`getglobalvar`、`setglobalvar` …） | 同上，但当作**会话变量**：不再跨聊天共享 |
| 其他（`{{original}}`、`{{input}}` …）、嵌套的宏 | 原样保留，所在的词条**停用**，报告里写明是哪个宏 |

**改变量的宏放在哪里很要紧。** 酒馆每次拼提示词时都会执行它们；我们这里只有聊天记录能改变量，词条只能读。所以：

| 所在位置 | 读变量、随机 | 改变量 |
|---|---|---|
| 词条（角色设定、世界书……） | 转换 | 词条停用。若是用来设初始值，写进角色卡的初始变量 |
| 开场白 | 转换，新会话时求值一次 | 变成第一条消息上的变量操作 |
| 正则 · 返回时 | 正则停用（结果会存进正文，我们不在那时求值） | 变成编辑块，回复收下时生效 |
| 正则 · 只作用于请求 | 转换，每次发送时求值 | 正则停用 |
| 正则 · 只作用于显示 | 正则停用（显示时不求值，请改用 HTML 组件） | 正则停用 |

返回时正则里，值只是捕获组（`{{setvar::hp::$1}}`）时写成 `hp = $1`，替换后就是数字；其他值加引号当文字。

`random`、`roll` 放在正文前会让缓存每次都失效，风险检查会提示。

## 正则

| 酒馆 | 导入后 |
|---|---|
| 作用于：用户输入 / AI 输出 | 作用于：用户消息 / AI 回复 |
| 仅格式显示 | 运行时 · 只作用于显示 |
| 仅格式提示词 | 运行时 · 只作用于请求 |
| 都不勾 | 返回时（改存下来的正文） |
| 替换文字里的 `{{match}}` | `$&` |
| 仅格式显示的正则替换出 HTML（例如状态栏） | 包成 ```` ```html ```` 代码块，作为[组件](variables.md#html-组件)在沙箱里渲染 |
| 列表顺序 | 优先级：越靠前越高 |

只作用于世界书、推理、斜杠命令的正则，正则写错的，替换文字里的宏在那一步不能用的（见上表），都会导入但停用。修剪字符串、作用深度限制忽略。

## 头像

PNG 角色卡导入时图片就是头像。也可以在角色详情里点头像换图（PNG、JPEG、WebP、GIF，10 MB 以内），或者移除。
