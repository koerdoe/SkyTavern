# 请求结构

左栏“请求结构”把预设、角色卡、用户自机、打开的世界书里的词条合并成一个列表。**从上往下，就是实际发给模型的顺序。**

## 四个分区

每个词条属于一个分区，分区的先后是固定的：

| 分区 | 放什么 | 标签 |
|---|---|---|
| 系统提示 | 总体指令 | 系统 |
| 正文前 | 角色设定、世界观等，缓存期间保持不变 | 前 |
| 正文 | 聊天记录；词条用深度 Dx 插在记录中间 | D0、D2… |
| 正文后 | 状态、提醒等每轮都可能变化的内容 | 后 |

每个位置法词条变成请求里单独的一条消息，保留它的角色（system / user / assistant）。内容为空的词条（例如没填的用户设定）不会发送。

> Claude 和 Gemini 只允许 system 消息出现在最前面。正文后的词条如果用 system 角色，发送时会报错并指出是哪个词条，把它改成 user 即可。

## 优先级

同一分区内，**优先级大的在前**；优先级相同时，按词条 ID 排。

- 普通词条的优先级在 −10000 到 10000 之间。
- 只有预设可以用超过这个范围的值，把词条固定在分区最顶（> 10000）或最底（< −10000）。这些词条受保护，插入规则碰不到它们。

角色卡和世界书导入时使用这些基础优先级（都在正文前）：

| 内容 | 优先级 |
|---|---|
| 世界书（前） | 5000 起 |
| 用户设定 | 4000 |
| 角色设定 | 3000 |
| 场景 | 2000 |
| 世界书（后） | 1000 起 |

预设里要排在世界书前面的词条，设为 6000 以上。

### 撞车避让

不同来源的词条在同一位置撞上同一个优先级时，先处理的保持原值，后处理的自动 +1，直到有空位。处理顺序是：预设 → 角色卡 → 用户自机 → 世界书（多本世界书按 ID 排）。同一来源内部优先级相同不会避让，按 ID 排。

避让只是为了让列表显示的就是真实顺序，不会改动词条本身。列表里显示为 `5000 (+1)`：原值加上被挪了多少。

## 正文里的深度 Dx

正文分区的词条用深度决定插在哪里，**从聊天记录的末尾往前数**：

- `D0`：最后一条消息之后。
- `D2`：倒数第二条消息之前。
- 深度超过记录条数时，放在记录最上方。

只数聊天记录本身，不数插进来的词条，也不数[附加消息](variables.md#附加消息)。聊天记录被裁剪后，深度按剩下的记录重新计算。

## 插入法

除了“放在某个位置”，词条也可以**插进别的消息里**：写一条正则，在匹配到的地方用模板替换。

- **正则**只在单条消息内匹配，不跨消息。可以选择匹配哪些分区（正文前 / 正文 / 正文后）。
- **模板**就是词条内容。`$1`、`$2` 是捕获组，`$&` 是整个匹配，`$<名字>` 是命名组，`$$` 是字面的 `$`。引用不存在的组会被当作写错，不能保存。
- **多处匹配**时取第一处或最后一处；**没匹配到**时可以提示警告或保持静默。
- 每条插入规则每次请求只执行一次。插入规则在所有位置法词条放好之后，按优先级依次执行，后执行的可以匹配到前面插入的内容。
- 插入只影响这一次请求，不会改动聊天记录。

例：在场景描写后面补一句天气。

```
正则：   (【场景】)
模板：   $1窗外正下着雨。
```

## IF 条件

每个词条都可以写一个条件，不成立就不发送：

```
hp < 30
has("任务") && 任务 == "护送"
!has("已见过艾琳")
商品.灵泉水.库存 > 0 && len(背包) < 10
mentioned("艾琳", "Eileen")
similar("北塔的地下室", 0.6)
```

- 可以读取变量（见[变量与正则](variables.md)）以及 `char`、`user`、`$date`、`$time`、`$weekday`。用 `.` 取对象的字段或列表的第几项。
- 支持 `! && || == != < <= > >= + - * / %` 和括号。字符串用引号。
- `len(值)`：文字的字数、列表的项数、对象的字段数。
- `get("名字", 默认值)`：变量不存在时返回默认值（不写就是空文字），不会报错。
- `mentioned("词", …)`：最近几条聊天记录里提到了其中任意一个词。默认看最近 2 条，第一个参数写数字可以改，例如 `mentioned(6, "灯塔")`。不区分大小写；纯英文数字的词按整词匹配（cat 不会匹配 category），中文等按包含匹配；写成 `"/灯塔|塔楼/"` 按正则匹配。检查的是本次请求用到的聊天记录（裁剪之后的）。用它可以做按内容触发的世界书，建议放在正文后或 Dx，放在正文前会让缓存失效。
- `==` 不做类型转换：`30 == "30"` 不成立。列表和对象按内容比较。
- 空文字、0、空列表、空对象都算不成立。
- 读取不存在的变量会**停止生成**并指出是哪个词条。不确定变量在不在时，先用 `has("名字")` 判断，或者用 `get()`。
- `random(…)`、`pick(…)`、`roll(…)` 也能用，见下面的[占位符](#占位符)。

### 按相似度触发 similar()

`mentioned()` 只认字面上的词；`similar()` 用嵌入模型比较**意思**，换个说法也能触发：

| 写法 | 含义 |
|---|---|
| `similar()` | 用这个词条自己的内容，和最近 2 条消息比，相似度 ≥ 0.5 成立 |
| `similar(0.6)` | 小于 1 的数是阈值 |
| `similar(4)` | 1–100 的整数是检查最近几条消息 |
| `similar("北塔的地下室")` | 用写明的描述去比。词条内容很长、或者混了很多别的东西时，用一句话概括它的主题效果更好 |
| `similar(4, "北塔", 0.6)` | 都写也行，顺序不限 |

- 每条消息按召回的方式切块，取最近几条消息的所有块里和查询最相似的那一块的分数。
- 过了阈值的词条按分数从高到低，**最多取前几条**（系统设置 → 召回，默认 5），其余这次不发送。这样换了嵌入模型、分数整体偏高或偏低时，也不会一下触发一大片。
- 参数只能直接写数字和文字，不能用变量或算式（生成前要先把它们找出来算好）。
- 需要打开召回并选好嵌入模型（见[召回](#召回)）。没开时一律不成立，左栏这个词条旁边显示“≈ 未算”，预览里有提示，但不会报错。编辑预设时的预览没有聊天记录，也一律不成立。
- 开着时，左栏词条旁边显示这次的相似度（例如 `≈0.62`），绿色表示成立；悬停看阈值和没成立的原因。不同嵌入模型给出的分数范围差别很大，阈值照着这个数调。
- 嵌入接口出错时停止生成并给出原因，和召回一样。
- 和 `mentioned()` 一样，建议放在正文后或 Dx，放在正文前会让缓存失效。

## 占位符

词条内容里可以写 `{{名字}}`，发送时换成对应的值：

| 写法 | 值 |
|---|---|
| `{{char}}` | 角色名 |
| `{{user}}` | 用户自机的名字 |
| `{{hp}}`、`{{商品.灵泉水.价格}}` 等 | 变量的当前值；列表和对象展开成 JSON |
| `{{$date}}` `{{$time}}` `{{$weekday}}` | 当前日期、时间、星期 |
| `{{$recall}}` | 召回到的过往片段，没有时为空文字，见[召回](#召回) |
| `{{$lastMessage}}` `{{$lastUserMessage}}` `{{$lastCharMessage}}` | 最近一条消息、最近一条用户消息、最近一条角色消息 |
| `{{get("金币", 0)}}` | 变量的值，不存在时用默认值（不写就是空文字），不会报错 |
| `{{random("晴", "雨", "雾")}}` | 随机选一个，**每次请求都重新抽** |
| `{{pick("晴", "雨", "雾")}}` | 随机选一个，但同一个会话里总是同一个 |
| `{{roll("2d6+1")}}` `{{roll(20)}}` | 掷骰：2 个六面骰加 1；一个 20 面骰 |

括号写法就是 IF 里的函数，参数规则一样。

想写字面的花括号，在前面加反斜杠：`\{{总属性}}` 发送时是 `{{总属性}}`，不当作占位符；`\{` 一律输出 `{`。

词条里的占位符找不到对应的值（或者函数写错）时会停止生成。聊天记录里的占位符只替换找得到的，找不到的原样保留。开场白里的 `random` 等在新会话开始时抽一次，之后固定。

`random`、`roll`、`get` 和变量一样会变，放在正文前会让缓存失效；`pick` 在同一会话里不变，不影响缓存。

## 召回

聊天变长后，较早的内容会被裁出正文窗口（见[请求参数与缓存](request-params.md)）。召回会从**窗口之外**的记录里找出和最新一条用户消息相关的片段，通过 `{{$recall}}` 放进你写的词条里。

**开启**：默认是关闭的。在系统设置 → 召回里打开开关，再选一个嵌入模型（见下文），并确认请求结构里有词条用到了 `{{$recall}}`。那一页有个按钮可以往当前预设加一条现成的：

```
分区：正文后　角色：user　IF：$recall != ""
以下是与当前对话相关的过往片段，供参考：
{{$recall}}
```

没有任何启用的词条用到 `$recall` 时不会召回，也不会花钱。

打开后用的是**向量**匹配：用嵌入模型比较意思，换个说法也能找到。开关旁边的“匹配方式”里还有两个备选，一般用不到：

| 匹配方式 | 怎么找 | 需要 |
|---|---|---|
| 向量（默认，推荐） | 比较意思 | 一个嵌入模型 |
| 向量 + 关键词 | 两者分数各占一半；人名、地名更容易命中，但也更容易被字面相同、意思无关的片段带偏 | 一个嵌入模型 |
| 只用关键词 | 只看字面上相同的词（中文按相邻两字），换个说法就找不到 | 什么都不用 |

**嵌入模型**：在“模型配置”里新建一个，**用途**选“嵌入”。OpenAI 兼容的渠道发到 Base URL 下的 `/embeddings`（如 `text-embedding-3-small`），Gemini 用 `batchEmbedContents`（如 `gemini-embedding-001`）。Claude 没有嵌入接口。嵌入模型不能用来对话。

**结果长什么样**：聊天记录按段落切成约 100–500 字的块。取得分最高的若干块（“取前几条”，默认 3），每块再带上前后各一块，按原来的顺序排好，标上是谁说的；不相连的片段之间用“……”隔开：

```
艾琳：老人把一把蓝色钥匙塞进你手里……
……
旅人：那我们明天去北塔看看。
```

几点说明：

- 正文窗口里已经有的消息不会被召回，不会重复。
- 召回结果让请求变长，可能让窗口再往后裁一点，这是正常的。
- 向量模式下，新消息进入会话后在后台建索引；没建好的部分在下次需要时当场补，嵌入接口出错则那次生成停止并给出原因。索引状态和手动重试在 /admin。消息删除、编辑后索引会自动跟着更新。

## 预览：看它最终变成了什么

列表每行右边的徽标说明这个词条这次的去向：

| 徽标 | 含义 |
|---|---|
| `#3` | 在第 3 条消息 |
| `→#6` | 插入规则插进了第 6 条消息 |
| `IF 否` | 条件不成立，这次不发送（名称带删除线） |
| `空` | 内容为空，没有发送 |
| `未命中` | 插入规则没有匹配到任何消息 |
| `⟂#2` | 手动缓存断点落在第 2 条消息 |

**点徽标**，中间栏会切到“预览”并定位到那条消息。预览里每条消息都标明来源、分区和角色，还会标出：

- **被插入 ×n**：被几条插入规则改过。
- **受保护**：来自超出 ±10000 的预设词条。
- **易变**：每轮都可能变化，缓存不会越过它。
- **缓存复用到这里**：缓存断点的位置，见[请求参数与缓存](request-params.md)。

预览顶部可以切换到“请求体”，看发给模型的完整 JSON（只读，不含密钥）。

## 编辑词条

- **点一行**展开编辑；新建的词条会自动展开。按 Ctrl/⌘+S 保存。
- **拖动**一行到另一行的上方或下方，优先级会自动设成目标的 +1 或 −1；拖到别的分区会一并改分区。
- 预设的 **JSON 模式**（`<>` 按钮）可以整份编辑，格式不对时不能保存。
- 有未保存的修改时离开，会提示保存、放弃或留下。

### 风险提示

保存或打开时会粗略检查两类风险，发现时提示一次，确认后只要相关配置不变就不再提示：

- **缓存破坏**：正文前的词条带 IF、用了会变化的占位符，或者插入规则会修改聊天记录。这些都会让缓存更容易失效。
- **递归插入**：一条插入规则的正则能匹配到另一条插进去的内容，结果可能不是你预期的。
